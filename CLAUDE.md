# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Reelish — engineering rules for AI agents

Reelish (package `onfeed`) is a Flutter app for discovering movies and series
(TMDB metadata) and playing them through user-installed third-party provider
plugins. It ships for **Android phones and tablets, Android TV / Google TV,
and Windows**. iOS, macOS, Linux and web folders exist but are not shipped.

Architecture details live in the `reelish-architecture` skill; read it before
non-trivial changes. Skills are in `.claude/skills/` (index at the end). The
developer documentation starts at `docs/README.md`; its code references are
generated by `dart run tool/docs/docs_tool.dart generate`, and
`dart run tool/docs/docs_tool.dart check` must pass after code moves or doc
changes. A new file under `lib/` fails the check unless it starts with a
`//` purpose comment (above the imports) or its same-named type has a doc
comment.

## Platforms are separate interfaces

`DeviceCapabilities` (`lib/src/platform/device_capabilities.dart`) chooses
the interface once per launch:

| Platform | Interface | Input |
|---|---|---|
| Phone / tablet | `lib/src/screens/` + `SoftGlassDock` | Touch |
| Android TV / Google TV | `lib/src/screens/tv/`, `lib/src/widgets/tv/` | D-pad focus (`TvFocusable`) |
| Windows | `lib/src/desktop/` (`DesktopShell` sidebar) | Mouse, keyboard, gamepad |

- `usesTvLayout` is true on TV **and** Windows; `isTv` is real TV hardware
  only; `isDesktop` is Windows. Pick the flag that matches the intent.
- Shared below the UI: models, services, ViewModels, the player chrome
  (`lib/src/widgets/player/`), and the phone Settings/Plugins sub-pages
  that the TV and Windows pages reuse.
- Styling comes from `GlassTheme` (`lib/src/theme/glass_theme.dart`;
  colours, Montserrat; the bundled Bebas Neue is only for the phone Top 10
  numerals) and `lib/src/theme/design_tokens.dart` (`AppSpace`,
  `AppRadius`, `AppTextSize`/`AppType`, `AppIcon`, `AppMotion`). The accent
  is user-selectable: read `GlassTheme.primary`, never hard-code coral. Run
  animation durations through `AppMotion.resolve` so reduced motion applies.
- Icons are Reelish's own: `ReelishIcons` (`lib/src/theme/reelish_icons.dart`), a
  font generated by `tool/icons/`, never another icon set. `Icon.fill` does
  nothing; use the `...Filled` form or `ReelishIcons.filled`. See
  `docs/design/icon-system.md`.
- `TvDestination` (`lib/src/navigation/app_destination.dart`) feeds both the
  TV rail and the Windows sidebar, and the page switches in `home_screen.dart`
  are exhaustive: a new value appears on both and needs a page for each
  (Profile is drawn with the avatar; the TV rail puts it first via
  `tvRailOrder`). The phone uses its own dock tabs (`_selectTab`).

## Accounts, the Reelish API and Watch Party

- **Reelish API** (`backend/`, TypeScript Cloudflare Worker, all routes under
  `/api/v1`): Trakt sign-in (device code; browser via PKCE and the Worker's
  own HTTPS callback), Reelish sessions (short access tokens, rotating
  refresh tokens — reuse revokes the session), encrypted Trakt token custody,
  the allowlisted TMDB gateway, watchlist sync and episode checks. D1 holds
  accounts; migrations are `backend/migrations/NNNN_*.sql`. Background
  episode checks use a narrow per-session `rnt_` alert token because they
  cannot safely rotate a refresh token; a lost Trakt grant answers 409, not
  401, so the app is not signed out. Docs: `docs/backend/README.md`
  (routes, Watch Party protocol) and `docs/backend/operations.md`.
- **Badges** (`backend/src/badges.ts`, `docs/backend/badges.md`) are identity and
  never a permission; nothing may check one before allowing an action. Founder
  comes from the `FOUNDER_TRAKT_UUID` Worker secret, never a name or client data.
- **Supporters:** the Supporter Badge is set only by Buy Me a Coffee's signed
  webhook, or the owner's `backend/scripts/grant-supporter.mjs`; never by the
  app. A donation names its account through a code in the donor's message,
  since the platform has no metadata. Its one server-checked privilege is hosting a Watch
  Party: `createParty` checks the donation record (`isActiveSupporter`), never
  the badge or client data; joining stays open to everyone. Supporters also
  get profile themes (`supporter_themes.dart`), drawn only while
  `SupporterController` reports a verified donation, and every launcher icon
  (`app_icon.dart`: Default and Slate stay free; a supporter icon is applied
  only after a fresh server check). Docs: `docs/backend/supporters.md`,
  `docs/features/supporter-themes.md`, `docs/features/app-icons.md`.
- **Environments:** `staging` and `production` in `backend/wrangler.toml`
  (release builds point at production via the `REELISH_API_URL` repository
  variable). Deploy and migrate staging first; touch production only when
  the user explicitly says so. Ship migrations to production before a
  release that depends on them.
- **App side:** `lib/src/account/` (`AccountController` with `accessToken()`
  refresh, `AccountApi`, `ProfileController` — display name and avatar are
  device-local per account, a photo is never uploaded). `AccountGate`
  (`sign_in_screen.dart`) shows sign-in whenever no one is signed in, so
  there is no guest state inside the app.
- **Watch Party:** one SQLite-backed Durable Object per 8-digit code
  (`backend/src/party-room.ts`, WebSocket Hibernation API; must stay within
  the Workers Free plan: write storage only on state changes, no per-second
  traffic). The room is the playback authority (sequence-numbered timeline);
  clients (`lib/src/watch_party/`) sync with clock offset and drift rules in
  pure Dart. A seek leads the room by its measured cost, and a buffering
  player is left alone unless the room changed: seeking to where the room is
  now, or again while buffering, loops forever on a slow stream. The player hook is one optional `PartyPlayerSync` created in
  `CustomVideoPlayer` only when the active party plays that title: it is
  null otherwise, and room commands go through `_PartyHandle` (the remote
  path), never `_togglePlay`/`_seekTo`, so they are not echoed back. Home
  registers `PartyPlayerLauncher.open` so parties reuse the normal source
  search.
- **Release obfuscation check:** CI fails if `package:onfeed/src` survives
  in the compiled app. A `@pragma('vm:entry-point')` callback (WorkManager,
  notification handlers) keeps its library URI, so define it in
  `lib/main.dart`, not under `lib/src/`.

## Analytics and crash reports

Firebase runs through the Android SDK and the app's own method channels, not
FlutterFire: `firebase_core` would build the C++ SDK into Windows. Both are
opt-in, each with its own consent, and Firebase is not started before a yes.
Report failures through `CrashReporter` (`lib/src/diagnostics/`): pass an
error's type and fixed text, since error messages quote stream URLs and remote
data, and call `note` for expected failures. Windows keeps a local log only.
`--dart-define=REELISH_CRASH_TEST=true` adds test crashes and must never reach a
release. Docs: `docs/features/analytics.md`, `docs/features/crash-reporting.md`.

## Non-negotiable rules

1. **Verify before you change.** Read the code; never assume an
   architecture, a feature or a platform behaviour from a prompt or a doc.
   `docs/` holds useful audits, but some describe past states.
2. **Platform isolation.** Prefer a platform-specific widget over editing a
   shared one. If a shared file must change, make it inert on the other
   platforms (e.g. hover-only, or behind a flag) and say so.
3. **Playback integrity.** Do not change engine selection, source
   discovery/validation/preparation, stream headers or redirects, subtitles,
   audio tracks, or provider execution unless the task is about them and the
   change is verified. Never "tidy" working playback code.
4. **Untrusted input.** Provider scripts, manifests, stream URLs, subtitle
   files and remote responses are untrusted. Never weaken
   `NetworkDestinationValidator`, the QuickJS limits, script-change
   approval, or Authenticode checks to make something work.
5. **Secrets.** The TMDB credential lives only in the Reelish API's Worker
   secrets (`backend/`, `docs/backend/operations.md`); the app has none and
   must never get one back. Never print, copy, commit or log secrets,
   session or Trakt tokens, keystore or signing material. Don't log full
   stream URLs or auth headers.
6. **Persisted data stays readable.** SharedPreferences keys and JSON shapes
   in `StorageService` are user data; keep old values loadable.
7. **Focused changes.** No broad refactors, new dependencies, or unrelated
   cleanup (including repo-wide `dart format`) without approval. Match the
   surrounding style and comment density.
8. **Commit, push, tag or release only when asked.**

## Commands

The catalog needs a Trakt sign-in against a deployed Reelish API: pass its
HTTPS address with `--dart-define=REELISH_API_URL=...` (ask for the staging
URL if you don't have it). Widget tests inject sessions and fakes instead.

```sh
flutter pub get
flutter run -d windows --dart-define=REELISH_API_URL=https://...   # Windows interface
cd backend && npm ci && npm test                   # Reelish API (Cloudflare Worker)
cd backend && npm run typecheck                     # tsc --noEmit
cd backend && npx vitest run test/<name>.test.ts -t "<test name>"   # one backend test
cd backend && npx wrangler d1 migrations apply reelish-staging --remote --env staging
cd backend && npx wrangler deploy --env staging     # production only when asked
flutter run --dart-define=REELISH_FORCE_TV=true     # TV interface on any device
flutter test test/<name>_test.dart                  # one test file
flutter test test/<name>_test.dart --plain-name "<test name>"   # one test
flutter test integration_test/<name>_test.dart -d <device>      # one file per run
flutter drive --profile -d <device> --driver=test_driver/integration_test.dart \
  --target=integration_test/ui_perf_test.dart       # frame timings
dart run tool/generate_plugin_catalog.dart          # regenerate assets/data/plugins.json
```

`test/flutter_test_config.dart` preloads
`third_party/flutter_js/windows/shared/quickjs_c_bridge.dll` so provider
tests can start QuickJS under `flutter test` on Windows. Native code lives
in vendored packages: `packages/video_player_media_kit` (libmpv bridge),
`packages/flutter_go_torrent_streamer` (Go torrent engine) and
`third_party/flutter_js` (QuickJS). Releases are built only by CI from a
version tag (`.github/workflows/`, `docs/releasing.md`).

## Validation expectations

- Run `dart format` on the files you touched only, then
  `flutter analyze lib test integration_test test_driver` (CI fails on
  warnings and errors; the baseline has 16 info-level notes) and
  `flutter test`.
- Backend changes: `npm run typecheck` and `npm test` in `backend/`. Tests
  run inside the Workers runtime (`@cloudflare/vitest-pool-workers`) with
  real D1, Durable Objects and WebSockets; `signIn()` in
  `backend/test/helpers.ts` fakes Trakt through one global fetch mock, so
  sign accounts in one after another, not in parallel.
- Build what you touched: `flutter build windows --release` for Windows,
  `flutter build apk --profile` for Android.
- Widget tests pick the interface with
  `variant: TargetPlatformVariant.only(TargetPlatform.windows)` (Windows) or
  `DeviceCapabilities.debugOverride` (TV). They draw text in the Ahem test
  font, far wider than Montserrat; load the real fonts with `FontLoader`
  (as `paused_overlay_test` does) before asserting layout.
- The Windows integration tests stream public test clips; a libmpv network
  error there (e.g. `tcp: ffurl_read`) is the host, not a regression.
- Report a test as passed only if it ran. Say what was not verified
  (device, TV, live provider, real window scaling).
- The `regression-check` skill has the full per-platform checklist.

## Reporting

End every task with: what changed (files), why, validation run and its
results, what was not verified, and possible regressions or follow-ups.
